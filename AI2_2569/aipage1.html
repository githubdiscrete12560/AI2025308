02 / FORMULATION

What exactly is a search problem?

Component8-puzzle definition
StateTuple of 9 entries, with 0 as the blank
ActionsMove blank up, down, left, or right when legal
TransitionSwap blank and adjacent tile
Initial stateScrambled arrangement
Goal teststate == GOAL
Path cost1 per slide; minimize total moves

State ≠ Search node

A state is a tile arrangement. A search node is a record used by a search algorithm (state, parent, cost, etc.). One state can appear in multiple paths.

03 / GRAPH

Why is this a graph, not just a tree?

State-space graph

Each legal board arrangement is a vertex; each legal slide is an edge. Every move can be undone, so cycles exist.

  • 9! = 362,880 permutations in total.
  • From any solvable board, exactly 181,440 arrangements are reachable.
  • A visited set prevents re-enqueuing repeated states in BFS.
The search tree is the paths generated by an algorithm; the state graph includes reverse edges and merging paths.

04 / VALID STATES

How do we generate a solvable board?

Random walk from the goal

Start from the goal and repeatedly make legal moves. This guarantees a reachable state, although undo moves can make the final puzzle easier than the number of shuffle steps suggests.

Exactly half of all tile permutations are in the goal's reachable component.

For reproducible classroom experiments, fix a random seed and report the actual optimal solution depth.
GOAL = (1, 2, 3, 4, 5, 6, 7, 8, 0)

def scramble(moves=25):
    state = GOAL
    for _ in range(moves):
        state = random.choice(list(neighbors(state)))
    return state
05 / CODE

How do legal moves create neighbors?

import random, heapq
from collections import deque

GOAL = (1, 2, 3, 4, 5, 6, 7, 8, 0)

def neighbors(state):
    i = state.index(0)
    r, c = divmod(i, 3)
    for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
        nr, nc = r + dr, c + dc
        if 0 <= nr < 3 and 0 <= nc < 3:
            j = nr * 3 + nc
            s = list(state)
            s[i], s[j] = s[j], s[i]
            yield tuple(s)

The graph is generated on demand: neighbors(state) creates outgoing edges when needed.

07 / BFS

What does BFS explore first?

First-in, first-out queue

BFS explores all depth-0 states, then depth 1, then depth 2, etc. With unit-cost moves it finds a shortest solution.

Why mark visited when enqueuing? It avoids putting the same board in the queue multiple times.

“Expanded” means removed from the frontier and processed, including the goal in this implementation.
def bfs(start):
    visited = {start}
    queue = deque([(start, 0)])
    expanded = 0
    while queue:
        state, depth = queue.popleft()
        expanded += 1
        if state == GOAL:
            return depth, expanded
        for nxt in neighbors(state):
            if nxt not in visited:
                visited.add(nxt)
                queue.append((nxt, depth + 1))

09 / HEURISTIC

Can we estimate distance to the goal?

Manhattan distance

Sum, for each numbered tile, the absolute row difference plus the absolute column difference between its current and goal positions. Ignore the blank.

h(s) = Σ (|r − rgoal| + |c − cgoal|)

For this board, tile 7 is one column from home and tile 8 is one column from home, so h = 2.

Each move shifts exactly one numbered tile by one cell, so Manhattan distance never overestimates the remaining number of moves.

11 / A*

How does A* choose the next board?

f(n) = g(n) + h(n)

g(n) is the known number of moves so far.

h(n) is the estimated number of moves remaining.

A* prioritizes the lowest f. Manhattan distance is admissible and consistent for the unit-cost 8-puzzle.

A* does not literally “prune” all worse-looking paths. It orders the frontier and can still explore apparently unpromising states if needed.

Example choices at depth 1

Moving right gives h = 1, g = 1, f = 2.

Moving up gives h = 3, g = 1, f = 4.

A* prefers the right move.

12 / A* CODE

How is A* implemented with a priority queue?

def manhattan(state):
    total = 0
    for idx, tile in enumerate(state):
        if tile:
            goal_idx = tile - 1
            total += (abs(idx // 3 - goal_idx // 3)
                      + abs(idx % 3 - goal_idx % 3))
    return total

def a_star(start):
    best_g = {start: 0}
    heap = [(manhattan(start), 0, start)]
    expanded = 0
    while heap:
        f, g, state = heapq.heappop(heap)
        if g > best_g[state]:
            continue                   # ignore stale entry
        expanded += 1
        if state == GOAL:
            return g, expanded
        for nxt in neighbors(state):
            ng = g + 1
            if ng < best_g.get(nxt, float("inf")):
                best_g[nxt] = ng
                heapq.heappush(heap, (ng + manhattan(nxt), ng, nxt))

15 / COMPARE

How would we compare algorithms in Python?

random.seed(1)
for _ in range(5):
    start = scramble(40)
    d1, n1 = bfs(start)
    d2, n2 = a_star(start)
    print(f"BFS={d1} moves, {n1} expanded | "
          f"A*={d2} moves, {n2} expanded")

Expected result

Both return the same optimal depth. Manhattan-guided A* typically expands far fewer states, especially on challenging puzzles.

Important caveat

A 40-step random walk does not imply a 40-move shortest solution. Measure the actual depth, and repeat across many start states for fair comparisons.

16 / THEORY

Why can A* remain optimal?

Admissible

h(n) ≤ true remaining cost. Manhattan is a lower bound because each legal slide shifts one tile by one cell.

Consistent

h(n) ≤ 1 + h(n′) for every single move. This makes A* graph-search optimal when implemented correctly.

Trade-off

A* uses more memory for its frontier and best-known costs. Informed search often reduces expansions, but doesn't eliminate exponential worst cases.

Consistency is the convenient stronger condition for the graph-search implementation shown; admissibility alone needs care with reopening states in general.

17 / MISCONCEPTIONS

Which statements need more precision?

“Heuristics prune states.”

More accurately, A* uses a heuristic to prioritize states. It doesn't simply discard every high-h state.

“BFS is A* with h = 0.”

With h = 0, A* becomes uniform-cost search; when all edges cost 1, it expands by increasing depth like BFS (tie order may differ).

“An admissible h always means fewer expansions.”

Not necessarily for every individual instance or tie order. Better heuristics often help, but counts depend on the algorithm's tie-breaking.
