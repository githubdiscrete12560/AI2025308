1. The 8-Puzzle: Problem Formulation

The 8-puzzle is a 3×3 grid with tiles numbered 1-8 and one blank space. You slide tiles into the blank until the board matches the goal state.

Formalizing the Problem

Element Description in the 8-Puzzle
State The arrangement of the 9 cells (e.g., (1,2,3,4,5,6,7,8,0) where 0 is the blank).
Actions Move the blank up, down, left, or right (if it stays on the board).
Transition Swap the blank with the neighboring tile.
Initial State The scrambled board.
Goal Test state == (1,2,3,4,5,6,7,8,0)
Path Cost 1 per move, so the cheapest path is the fewest moves.

This is a graph. Each board is a node, each legal slide is an edge, and the graph has 181,440 reachable states. Because cycles exist, a visited set is required.

2. Shared Setup & Scramble

Before implementing the algorithms, we need a way to generate neighboring states and create solvable scrambled puzzles.

import random, heapq
from collections import deque

GOAL = (1, 2, 3, 4, 5, 6, 7, 8, 0)

def neighbors(state):
    i = state.index(0)
    r, c = divmod(i, 3)
    for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
        nr, nc = r + dr, c + dc
        if 0 <= nr < 3 and 0 <= nc < 3:
            j = nr * 3 + nc
            s = list(state)
            s[i], s[j] = s[j], s[i]
            yield tuple(s)

def scramble(moves=25):
    # Random walk from the goal guarantees the puzzle is solvable
    s = GOAL
    for _ in range(moves):
        s = random.choice(list(neighbors(s)))
    return s

Note: Half of all random arrangements of the 8-puzzle are unsolvable, so scrambling by legal moves from the goal is the safe way to generate a start state.

3. Uninformed Search: BFS

Breadth-First Search (BFS) is the same BFS you already know. It explores every board 1 move away, then 2 moves away, and so on. It is guaranteed to find the fewest-move solution, but it has no idea which direction is "toward" the goal, so it expands a huge number of irrelevant boards.

def bfs(start):
    visited = {start}
    queue = deque([(start, 0)])
    expanded = 0
    while queue:
        state, depth = queue.popleft()
        expanded += 1
        if state == GOAL:
            return depth, expanded
        for nxt in neighbors(state):
            if nxt not in visited:
                visited.add(nxt)
                queue.append((nxt, depth + 1))

4. Informed Search: A*

A* picks the next node by f(n) = g(n) + h(n):

  • g(n): moves made so far (known cost)
  • h(n): estimated moves remaining (the heuristic)

For h, we use Manhattan distance: for each tile, count how many rows plus columns it is from its goal position, and sum them.

def manhattan(state):
    total = 0
    for idx, tile in enumerate(state):
        if tile != 0:
            goal_idx = tile - 1
            total += abs(idx // 3 - goal_idx // 3) + abs(idx % 3 - goal_idx % 3)
    return total

def a_star(start):
    best_g = {start: 0}
    heap = [(manhattan(start), 0, start)]
    expanded = 0
    while heap:
        f, g, state = heapq.heappop(heap)
        if g > best_g[state]:
            continue  # stale entry
        expanded += 1
        if state == GOAL:
            return g, expanded
        for nxt in neighbors(state):
            ng = g + 1
            if ng < best_g.get(nxt, float("inf")):
                best_g[nxt] = ng
                heapq.heappush(heap, (ng + manhattan(nxt), ng, nxt))

5. Comparison & Why This Works

When you run the comparison, you should see two things:

  1. Both report the same solution length. A* is still optimal here, because Manhattan distance never overestimates the true remaining cost (it is admissible).
  2. A* expands far fewer nodes, and the gap grows as the puzzle gets harder to solve.

Why this works:

  • Admissible heuristic: Every tile needs at least its Manhattan distance in moves, so h never overestimates. That is the condition for A* to stay optimal.
  • Heuristics prune, not guess: A* does not skip the optimal path. It just postpones boards that look far from the goal.
  • BFS is a special case of A*: Set h(n) = 0 and A* behaves like uniform-cost search, which is BFS when every move costs 1. A better heuristic means less wasted search.
  • Better heuristics are a design problem: Try replacing Manhattan with "number of misplaced tiles." It is also admissible but weaker, so A* will expand more nodes. A stronger heuristic means less search.

6. Visualizing the Search Tree

Explanation of the Search Tree

The image above illustrates the search tree for the 8-puzzle. It shows how a search algorithm explores possible moves from the starting state until it reaches the goal.

  • t0 (Start): The initial scrambled board. The blank is at the bottom left.
  • t1 (1 move): The two possible legal moves from the start state. The blank can slide up or right. The tree branches into two children.
  • t2 (2 moves): The tree expands further. Notice how some branches show duplicate states (a cycle) or states that don't lead to the goal. The algorithm must keep track of visited states to avoid infinite loops.
  • t3 (3 moves): The tree continues to expand. One of the nodes at this depth matches the goal state (top-left corner numbers 1,2,3 in the first row, and blank at the bottom right). The search stops here (indicated by "goal found, stop here").

Key Takeaway: This visualizes uninformed search (like BFS). The algorithm explores level by level. In contrast, A* would use a heuristic to prioritize exploring the branch that looks closest to the goal, skipping many of the nodes shown on the left side of this tree.
